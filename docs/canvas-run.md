# 画布运行、复用与媒体引用

> 状态：已实现；按 2026-09-14 代码校准。

本文说明手动画布的保存、运行、增量复用和最终合成。Agent 计划也会落到同一种画布图并共用运行基础设施，但 Agent 的计划生命周期和事件协议见 [agent-v3-design.md](agent-v3-design.md)。

## 节点与连接

画布支持六类节点：

| 节点 | 用途 | 主要输入/输出 |
| --- | --- | --- |
| `prompt` | 保存镜头提示词 | 输出文本 |
| `image` | 本地图片或公网图片素材 | 输出图片 |
| `video` | 本地视频、公网视频或上游生成结果 | 输出视频 |
| `audio` | 本地音频或公网音频 | 输出音频 |
| `generate` | 选择模型、方式和参数并生成镜头 | 输入提示词/媒体，输出视频 |
| `output` | 对多个生成片段排序、设置转场并拼接 | 多视频输入，输出最终视频 |

`canvas_graph.validate_graph()` 是图结构校验的权威入口。它会检查节点类型、边的输入/输出类型、目标 handle、单连接/多连接限制、模型能力和媒体槽位上限。

- 普通提示词、首帧、尾帧槽位只允许一条入边。
- R2V 聚合素材槽允许多条同类型入边，但不得超过模型目录中的上限。
- 输出节点允许连接多个生成节点。
- 生成节点可以把上游生成视频作为参考视频，因此生成节点之间可能形成执行依赖；循环图会被拒绝。

## 三种运行入口

### 单生成节点

生成节点上的“运行/重新生成”只提交该节点。运行前先保存画布并冻结该节点的实际输入；成功结果会写回节点，之后可以被整图运行复用。

接口：

```http
POST /api/canvases/{canvas_id}/nodes/{node_id}/run
Content-Type: application/json

{"revision": 12}
```

### 一键运行画布

“一键运行画布”先保存当前编辑，再对整张图执行原子预检和增量编译：

1. 校验画布版本、节点、连线、权限、参数和所有媒体输入。
2. 冻结本轮完整输入和输出顺序。
3. 计算每个节点的输入指纹，确定复用或重新执行。
4. 为需要执行的生成/合成节点建立 `AgentRun` 和 `AgentTask`。
5. 按依赖关系调度，独立镜头最多以 `AGENT_RUN_CONCURRENCY` 并发。
6. 所需镜头完成后，输出节点按冻结顺序自动合成。

接口：

```http
POST /api/canvases/{canvas_id}/run
Content-Type: application/json

{"revision": 12}
```

若没有输出节点，前端会创建一个输出节点并按画面位置连接现有生成节点；若已有输出节点但没有片段连接，运行会要求用户先完成连线。

### 手动重新合成

输出节点的“重新合成”只读取已经成功的镜头，不调用视频生成模型：

```http
POST /api/canvases/{canvas_id}/output/{node_id}/compose
Content-Type: application/json

{"revision": 12}
```

片段缺失、失败、过期或无法下载时直接报错，不会自动重新生成并产生费用。

## 增量复用规则

生成节点的复用依据是实际生成输入，不是节点更新时间。以下变化会使相应节点重新执行：

- 提示词或附加提示词变化；
- 模型、生成方式、分辨率、比例、时长、水印、音频等参数变化；
- 素材连接、素材 URL、素材顺序、用途说明或引用绑定变化；
- 作为参考视频的上游结果变化；
- 旧结果失败、过期，或者没有可恢复的视频来源。

以下变化不会重新生成镜头：

- 移动节点或修改节点尺寸；
- 平移/缩放画布；
- 仅调整输出节点中的片段顺序或转场；
- 其他与该生成节点无依赖关系的分支变化。

如果成功记录只有供应商在线地址或本地文件已丢失，运行器会先尝试下载旧结果供拼接。下载失败时停止并说明原因，不把“恢复文件失败”偷偷变成一次新的付费生成。

## 依赖、失败与重试

- 没有依赖关系的镜头可以并发执行。
- 引用上游生成视频的节点会等待上游成功，再使用本轮冻结的上游结果。
- 一个镜头失败只阻断依赖它的下游节点；无关分支继续完成。
- 再次运行画布时，未修改的成功镜头继续复用，失败、被阻断或输入变化的分支重新执行。
- Agent 运行的“重试”只重置失败/取消/阻断节点及其下游，并受 `AGENT_TASK_MAX_ATTEMPTS` 限制。
- “取消”会立即取消尚未开始的任务；已经提交给视频供应商的任务不保证可远程撤回。

## 输入冻结与迟到结果

每次运行保存不可变的 `input_snapshot`、画布修订号和节点输入指纹：

- 运行开始后编辑画布，不会改变在途供应商请求。
- 仅移动节点时，迟到结果仍可以安全回填。
- 提示词、参数、素材、连接或输出顺序发生影响输入的变化后，旧结果不会覆盖新画布状态。
- 同一修订的重复/并发启动会被拒绝，避免重复提交和重复扣费。

## 参考素材编号

R2V 节点的“素材引用”面板会为图片、视频和音频分别建立稳定引用：

- 编辑提示词时插入 `{{图片1}}`、`{{视频1}}`、`{{音频1}}` 等稳定标记。
- 可为每份素材填写用途，如“主角外观”“镜头运动”“对白声音”。
- 可以调整同类素材的实际发送顺序；稳定标记仍绑定原来的连线，发送时才转换为供应商表达。
- 断开被引用的素材后，运行会拒绝旧引用，避免编号静默指向另一份素材。

供应商转换：

| 模型 | 实际表达 |
| --- | --- |
| Wan | `图 1`、`视频 1`、`音频 1` |
| HappyHorse | `[Image 1]`、`[Image 2]` |
| MiniMax | `第 1 张参考图片`、`第 1 段参考视频`、`第 1 段参考音频` |

“查看实际发送的提示词”可以检查转换结果。单节点和整图运行使用相同的引用绑定逻辑，提示词和媒体顺序在启动时一起冻结。

## 输出节点与 FFmpeg

输出节点保存：

- 参与合成的生成节点 ID；
- 用户排序后的片段顺序；
- 相邻片段使用的转场设置；
- 合成结果文件名、播放地址或错误。

删除输出列表中的片段只移除它到当前输出节点的连接，不删除生成节点，也不影响该生成节点到其他输出的连接。多个输出节点会分别合成各自的片段集合。

合成由 FFmpeg/FFprobe 完成。生产 Docker 镜像已经安装它们；本地开发和测试需要自行安装并加入 `PATH`。

## 状态恢复 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/canvases/{id}/status` | 节点状态、错误和带签名的播放地址 |
| `GET` | `/api/canvases/{id}/runs/latest` | 恢复最近一轮整图运行及任务状态 |
| `POST` | `/api/canvases/{id}/run` | 启动整图增量运行 |
| `POST` | `/api/canvases/{id}/nodes/{node_id}/run` | 启动单生成节点 |
| `POST` | `/api/canvases/{id}/output/{node_id}/compose` | 手动重新合成输出 |

运行、任务和节点状态均持久化。刷新页面可以继续查询；应用启动时会恢复状态为 `queued` 或 `running` 的运行。

## 画布交互约定

- 输出节点可拖动片段行排序；转场跟随片段保存，`Escape` 可取消拖动。
- “素材库”支持上传或登记公网外链，双击/点击添加或拖拽到画布创建素材节点。
- 深浅主题由右上角开关控制，选择保存在浏览器端。
- 手工保存、Agent 计划导入和 Agent patch 最终都通过共享的事务化画布服务，不能绕过图校验和版本检查。
