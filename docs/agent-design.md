# 创作智能体 · 技术方案

> 状态：设计稿，未实现（v2，含复审修正）
> 定位：同时嵌入「生成工作台」与「创意画布」，共用一套技能库与大模型配置。

---

## 1. 参考来源说明

TapNow 的工作空间需要登录，内部产品文档拿不到。以下设计基于它**公开产品界面**提取的信号：

| 观察到的 | 推断的设计意图 |
| --- | --- |
| 单一输入框「今天要做点什么？」 | 自然语言是唯一入口，不让用户先学界面 |
| 输入框下的「手动确认」下拉 | 有自主性档位，AI 默认不擅自执行 |
| 「技能」区：H3 大师 skill / 视频编辑 / 增强现实 / 拼贴画 / 动效生成 / 音乐表演 | 能力被封装成**命名的、带说明的配方**，而非让模型自由发挥 |
| 快捷技能：白模视频预演 / 图片3D建模 / 角色工坊 | 高频场景前置成一键入口 |
| 模板库 + TapTV 的「查看创作过程」 | 流程可复用、可回放 |
| 产品名「你的智能体创意画布」 | 智能体不是附加的聊天窗，它**就是**操作画布的方式 |

最关键的一条：**技能（Skill）是让智能体可控的抽象**。模型不凭空编排，而是从技能库里挑一个配方，往里填参数。

---

## 2. 我们的智能体是什么

**不是聊天机器人，是编排器。**

产出不是一段文字，而是一份**可执行、可审阅的计划**：

- 工作台里 → 一次生成的完整参数
- 画布里 → 一组节点 + 连线

三件职责：

```
理解意图  →  选技能、填参数  →  产出待确认的计划
```

**它不直接执行。** 视频按秒计费，模型自作主张跑 20 个节点就是几百块。「计划先行 + 人确认」是成本闸门，不是产品花活。

## 3. 技能（Skill）

技能是一个**受 schema 约束的生成配方**：

```
Model(wan3.0) × Capability(t2v/i2v/r2v) × Preset(提示词模板 + 参数偏好) = Skill
```

### 3.1 技能规格

```jsonc
{
  "id": "consistent-character",
  "label": "角色一致性组镜",
  "description": "用同一批参考图跑多个镜头，保证人物在各镜头间不走样",
  "requires": {
    "capability": "r2v",
    "models": ["happyhorse-1.1-r2v", "wan3.0-video-prime"]
  },
  "inputs": [
    { "name": "character_images", "type": "image[]", "min": 1, "max": 9, "required": true },
    { "name": "shots",  "type": "text[]", "min": 2, "max": 6, "required": true },
    { "name": "style",  "type": "enum", "options": ["写实电影", "动画", "纪录片"] }
  ],
  "plan": "fanout",
  "max_nodes": 6          // 单个技能能产出的节点上限，防止模型编出 50 个镜头
}
```

### 3.2 首批技能清单

只做现有 5 个模型真能支撑的能力。TapNow 那些视频编辑、增强现实、空间追踪重绘都依赖我们尚未接入的模型能力，不照抄。

| 技能 | 用到的能力 | 计划形状 | 节点上限 | 适合 |
| --- | --- | --- | --- | --- |
| 一句话成片 | t2v | single | 1 | 最快路径 |
| 分镜短片 | t2v × N | storyboard | 6 | 脚本拆镜头 |
| 让图动起来 | i2v | single | 1 | 上传图 → 首帧动画 |
| 角色一致性组镜 | r2v × N | fanout | 6 | 保人物一致 |
| 商品多角度 | r2v × N | fanout | 6 | 电商多角度图 |
| 模型横评 | 同提示词 × 多模型 | compare | 3 | 并排比效果 |
| 迭代改进 | 基于已有结果 | refine | 1 | 「把猫换成狗」 |

### 3.3 为什么技能必须有 schema

模型填的每个参数都要过 `catalog.py` **现有的那套校验**——分辨率档位、画面比例、时长范围、图片数量上下限。

填错了（比如给 MiniMax 填 1080P），后端拒绝，回喂错误重试；仍不过就降级成「这一项我拿不准，你选一下」，附带合法选项的下拉。**绝不会把没校验过的参数提交给阿里云。**

重试预算按**整个计划**计，不是按节点：`AGENT_MAX_REPAIR_ATTEMPTS=2`。否则一个 6 节点的计划最坏要烧 12 次 LLM 调用。

## 4. 自主性与成本闸门

### 4.1 三档自主性

| 档位 | 行为 | 适用 |
| --- | --- | --- |
| **建议** `suggest` | 只给计划和理由，不碰画布/输入框 | 想先看看思路 |
| **手动确认** `confirm` ← 默认 | 计划落地但**不运行**，人点运行 | 日常 |
| **自动** `auto` | 直接跑 | 熟悉的固定流程 |

### 4.2 闸门按钱算，不按秒算

> **v1 的问题**：闸门只看「节点数 + 总秒数」。但 3 个节点 × 10 秒的 480P 和 1080P 差价可能三四倍，秒数根本代表不了成本。

改为**估算金额**。价格表放进配置，因为官方价格会变、也会有促销：

```ini
# 单价（元/秒），按 模型:分辨率 配置。缺失的档位回退到 AGENT_PRICE_DEFAULT
AGENT_PRICE_TABLE=happyhorse-1.1-t2v:720P=0.54,happyhorse-1.1-t2v:1080P=0.72,...
AGENT_PRICE_DEFAULT=0.8
AGENT_CURRENCY=CNY
```

估算函数：

```
plan_cost = Σ (单价[模型][分辨率] × 时长秒数)
```

三道闸门，任一超出即**自动降级为 confirm** 并说明原因：

| 闸门 | 默认 | 作用 |
| --- | --- | --- |
| `AGENT_MAX_AUTO_COST` | 20（元） | 单次自动执行的金额上限 |
| `AGENT_MAX_AUTO_NODES` | 3 | 节点数上限，防止批量小额绕过金额闸门 |
| `AGENT_DAILY_COST_LIMIT` | 200（元） | **每用户每日**累计上限，跨 plan 累加 |

前两道防单次失控，第三道防「一天点了 30 次」。

> 价格表默认值仅供起步，**上线前请对照百炼控制台的实际计费核对一遍**。估算只用于闸门和界面提示，不作为账单依据。

### 4.3 LLM 本身也要限流

模型调用也花钱。按用户限：

```ini
AGENT_RATE_PER_MINUTE=6        # 每用户每分钟最多几次智能体请求
AGENT_DAILY_TOKEN_LIMIT=200000 # 每用户每日 token 上限
```

复用已有的 `ratelimit.py` 滑动窗口实现即可。

## 5. 计划的生命周期

> **v1 的问题**：只有一个 `status` 字段，没说清它如何防重复接受、计划放久了怎么办。这是 v1 最实质的漏洞。

### 5.1 状态机

```
draft ──接受──▶ accepted ──执行──▶ executed
  │                                    
  ├──拒绝──▶ rejected                  
  └──超时──▶ expired
```

**`draft → accepted` 是一次性转换，用数据库条件更新实现**：

```sql
UPDATE agent_turns SET status='accepted'
 WHERE id = ? AND status = 'draft'
```

受影响行数为 0 就说明已被接受过，直接返回「这个计划已经执行过了」。这一条挡住：双击、两个标签页同时接受、网络重试。**没有它就是双倍扣费。**

### 5.2 计划会过期

计划生成后放着不动，这期间可能发生：

- 管理员下架了某个模型
- 用户被降级，不再有权用该模型
- 参考图的签名链接过期（默认 6 小时）
- 价格表被改了

所以**接受时必须完整重跑校验**，而不是信任生成时的结果：

```
接受计划
  ├─ 状态机检查（防重复）
  ├─ 重跑 can_use(role, model)        ← 权限可能变了
  ├─ 重跑 _validate(参数)              ← 模型可能下架
  ├─ 重跑 validate_graph(节点, 连线)   ← 画布计划的图校验
  ├─ 重新估算成本并二次确认（若涨幅 >10%）
  └─ 才 spawn(run_generation)
```

超过 `AGENT_PLAN_TTL_MINUTES=60` 的计划直接标 `expired`，让用户重新生成。

### 5.3 节点 id 由前端生成

计划里的节点 id **不能让模型编**——会重复、会和画布上已有节点冲突。模型只产出节点的**类型和内容**，id 在接受时由前端 nanoid 生成，与画布现有的做法一致。

## 6. 两个界面

### 6.1 工作台：智能体是「参谋」

输入框上方加入口。用户说「我想做一条 15 秒的产品广告，科技感，突出手机轻薄」，产出并**填进输入框等确认**：

```
提示词：超薄智能手机悬浮于深色渐变背景中，镜头缓慢环绕…（完整 200 字）
模型：  wan3.0-video-prime     理由：需要 15 秒 + 原生音频，只有它支持
参数：  1080P / 16:9 / 15 秒 / 音频开        预估 ¥10.8
```

它也能回答「这两个模型有什么区别」（读 `catalog.py`）、「我的图生视频为什么失败了」（读那条消息的 `error`）。

**读取范围严格限定在当前用户自己的数据**——查消息必须带 `user_id` 过滤，和现有接口一致。跨用户读取是越权。

### 6.2 画布：智能体是「编排者」

画布顶部一个输入条。一句话进去，产出一组节点和连线，**以半透明的「待确认」形态叠在画布上**：

```
┌─ 提示词(待确认) ─┐      ┌─ 生成 t2v (待确认) ─┐
│ 镜头1：晨雾中…  │─────▶│ wan3.0 · 1080P · 5s │
└─────────────────┘      └─────────────────────┘
┌─ 提示词(待确认) ─┐      ┌─ 生成 t2v (待确认) ─┐
│ 镜头2：蒸笼白气 │─────▶│ wan3.0 · 1080P · 5s │
└─────────────────┘      └─────────────────────┘

 [ 全部接受 ]  [ 逐个挑选 ]  [ 放弃 ]     4 个节点 / 20 秒 / 预估 ¥14.4
```

AI 生成的东西不能直接混进手工搭的图里。必须先可视化、可逐个拒绝，接受后才变成普通节点。

## 7. 架构与安全边界

```
用户一句话
   │
   ├─▶ [理解意图]  LLM：输出结构化意图
   ├─▶ [选技能]    规则预筛（权限、素材类型）+ LLM 打分
   ├─▶ [填参数]    LLM：按 schema 填空（JSON mode / function calling）
   │
   ═══════ 模型的输出到此为止：只能填 schema，不能构造任意调用 ═══════
   │
   ├─▶ [校验]      catalog.py + _validate + validate_graph
   ├─▶ [估成本]    价格表 × 时长
   ├─▶ [计划]      落库为 draft
   ├─▶ [人确认]    状态机转换 + 重跑校验
   └─▶ [执行]      spawn(run_generation)
```

**模型只做三件事：理解意图、选技能、填参数。** 它不调 DashScope，不写数据库，不能构造任意 API 请求。

这条边界同时挡住提示词注入：用户输入会进模型，但模型输出只能落进受约束的 schema。最坏情况是填出一组被校验拒绝的参数。

### 7.1 内容安全

> **v1 遗漏**：没考虑用户诱导模型产出违规提示词。

两层：

1. **系统提示词里明确约束**，模型自身会拒绝明显违规的创作请求
2. **阿里云的内容审核错误码单独处理**——命中审核不要当成普通失败重试（重试只会再撞一次并消耗额度），直接告诉用户「提示词未通过内容审核」并给出修改建议

### 7.2 参考图归属

> **v1 遗漏，且暴露了一个既有缺口**：`uploads.py` 目前只校验登录，**不记录文件归属人**。

现状下，任何登录用户拿到别人的图片文件名就能在自己的生成里引用它（文件名是 uuid，猜不到，但计划是可编辑的）。智能体会放大这个面。

建议在 A2 之前补上：`uploads` 表记录 `user_id`，计划接受时校验图片归属。这不是智能体引入的问题，但智能体让它更值得修。

### 7.3 复用现有代码

| 现有 | 角色 |
| --- | --- |
| `catalog.py` | 技能的能力约束来源 + 参数校验 |
| `conversations.py::_validate` | 计划落地前校验，一行不改 |
| `canvas_graph.py::validate_graph` | 画布计划的图校验 |
| `tasks.py::spawn` | 执行入口 |
| `ratelimit.py` | 智能体调用限流 |
| `prompt_context.py` | 保持不变，那是「提示词合并」的窄用途 |

## 8. 数据模型

```sql
agent_sessions
  id          TEXT PK
  user_id     TEXT FK
  surface     TEXT        -- studio | canvas
  target_id   TEXT        -- conversation_id 或 canvas_id
  created_at  DATETIME

agent_turns
  id             TEXT PK
  session_id     TEXT FK
  user_input     TEXT
  intent         JSON
  skill_id       TEXT
  plan           JSON       -- 节点 + 连线（无 id）+ 预估
  status         TEXT       -- draft | accepted | executed | rejected | expired | failed
  est_cost       REAL       -- 生成时的估算金额
  est_seconds    INTEGER
  model          TEXT
  tokens_in      INTEGER
  tokens_out     INTEGER
  repair_count   INTEGER    -- 用掉几次校验修复
  expires_at     DATETIME   -- 计划有效期
  created_at     DATETIME
  accepted_at    DATETIME

  UNIQUE 约束不够，接受走条件更新（见 §5.1）
```

保留计划的理由：可审阅、可回放（对应 TapNow 的「查看创作过程」）、可核算 token 与金额。

## 9. 大模型配置（`.env`）

兼容 OpenAI Chat Completions 协议，百炼兼容模式、DeepSeek、OpenAI、本地 Ollama / vLLM 都能接。

```ini
# ===== 创作智能体 =====
AGENT_ENABLED=true

# 接口协议。openai = 兼容 OpenAI Chat Completions
AGENT_PROVIDER=openai

# 接口地址：
#   阿里云百炼    https://dashscope.aliyuncs.com/compatible-mode/v1
#   DeepSeek      https://api.deepseek.com/v1
#   OpenAI        https://api.openai.com/v1
#   本地 Ollama   http://host.docker.internal:11434/v1
AGENT_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1

# 模型名。必须支持 JSON 输出或 function calling，否则参数填充不稳定
# 可选：qwen-plus / qwen-max / deepseek-chat / gpt-4o-mini
AGENT_MODEL=qwen-plus

# 留空则复用 DASHSCOPE_API_KEY_WAN
AGENT_API_KEY=

AGENT_TEMPERATURE=0.3
AGENT_MAX_TOKENS=2048
AGENT_TIMEOUT_SECONDS=60

# 默认自主性：suggest | confirm | auto
AGENT_AUTONOMY=confirm

# ---- 成本闸门（见 §4.2）----
AGENT_MAX_AUTO_COST=20
AGENT_MAX_AUTO_NODES=3
AGENT_DAILY_COST_LIMIT=200
AGENT_PRICE_DEFAULT=0.8
AGENT_PRICE_TABLE=
AGENT_CURRENCY=CNY

# ---- 调用限流（见 §4.3）----
AGENT_RATE_PER_MINUTE=6
AGENT_DAILY_TOKEN_LIMIT=200000

# ---- 计划 ----
AGENT_PLAN_TTL_MINUTES=60
AGENT_MAX_REPAIR_ATTEMPTS=2
AGENT_MAX_HISTORY_TURNS=8
```

### 设计取舍

| 问题 | 答案 |
| --- | --- |
| 为什么不复用 `CONTEXT_*` | 那套是「提示词合并」的窄用途，小模型够用。智能体要 function calling 和稳定 JSON，能力要求不同，该独立配、独立换 |
| 为什么用 OpenAI 兼容协议 | 不锁死阿里云。换 DeepSeek 省钱、用本地模型避免数据出网，改两行就行 |
| 为什么 `AGENT_API_KEY` 可留空 | 本机和小规模部署少填一项 |
| Docker 接本地 Ollama | 容器里的 `localhost` 是容器自己。用 `host.docker.internal`，compose 加 `extra_hosts: ["host.docker.internal:host-gateway"]` |
| LLM 挂了怎么办 | 明确降级：入口显示「智能体暂时不可用」，手工路径完全不受影响。不能转圈卡死 |

## 10. 交互打磨

### 10.1 进度要分阶段，不要转圈

计划生成要几秒到几十秒。用流式回传阶段：

```
理解意图 ✓  →  挑选技能 ✓  →  填写参数 ●  →  校验
                 已选「分镜短片」
```

用户能看到它在干什么，也能中途取消。

### 10.2 计划要能改，不是只能全接受

每个节点卡片上的参数可直接改（模型、分辨率、时长），改完成本估算实时更新。**不要逼用户在「全盘接受」和「全部放弃」之间二选一**——大多数时候只是某一项不满意。

### 10.3 理由要可见

每个决策附一句话，折叠展示：

```
模型  wan3.0-video-prime   ⓘ 需要 15 秒 + 原生音频，只有它支持
时长  15 秒                ⓘ 你说了「15 秒广告」
比例  16:9                 ⓘ 广告投放常用横屏
```

这决定了用户信不信任它。黑箱产出没人敢点「运行」。

### 10.4 成本前置到按钮上

```
[ 接受并运行 · 4 个节点 · 约 ¥14.4 ]
```

不要藏在角落。金额超过日限一半时按钮变琥珀色并提示剩余额度。

### 10.5 失败要可操作，不是报错

模型填错参数时，不弹「生成失败」，而是：

```
⚠ 分辨率这项我拿不准
  MiniMax H3 只有 768P 和 2K，我填了 1080P
  [ 768P ]  [ 2K ]        ← 直接点选
```

### 10.6 快捷技能芯片

学 TapNow，把高频技能放在输入框旁边，点一下就填好模板：

```
今天要做点什么？
[ 一句话成片 ]  [ 分镜短片 ]  [ 让图动起来 ]  [ 角色组镜 ]
```

### 10.7 空状态给示例

第一次进来不要是空输入框，给三条可点的示例提示词。这是新用户能否上手的关键。

### 10.8 可撤销

接受后 5 秒内显示「已提交 4 个任务 · 撤销」。auto 档尤其需要——那是唯一没有确认步骤的路径。

### 10.9 键盘

`Ctrl/Cmd + Enter` 提交、`Esc` 放弃预览层、`Tab` 在待确认节点间跳转。

## 11. 前端界面升级方案

### 11.1 现状与目标

当前已是深色 + 蓝紫渐变，但饱和度偏低、渐变用得较散。目标是往 TapNow 的观感靠：**近黑底、高饱和蓝紫渐变、渐变只用在极少数强调位、大量留白**。

### 11.2 色板

```css
:root {
  /* 高饱和蓝紫渐变 —— 只用在强调位 */
  --grad-primary: linear-gradient(120deg, #2E6BFF 0%, #7C3AED 46%, #C026D3 100%);
  --grad-primary-hover: linear-gradient(120deg, #4380FF 0%, #8B4BF0 46%, #D63FE8 100%);
  --grad-subtle: linear-gradient(120deg, rgba(46,107,255,.16), rgba(192,38,211,.16));

  /* 高饱和色在深底上必须配辉光，否则显脏 */
  --glow-primary: 0 0 24px rgba(124, 58, 237, .45);
  --glow-strong:  0 0 36px rgba(124, 58, 237, .62);

  /* 底色比现在更黑，向 TapNow 靠 */
  --bg:        #08080C;
  --surface-1: #101017;
  --surface-2: #16161F;
  --surface-3: #1D1D28;

  --border:      #23232E;
  --border-soft: #1A1A23;

  --text:   #F0F1F6;
  --dim:    #9FA0B2;
  --faint:  #6B6C7E;

  /* 语义色独立于品牌渐变，不参与渐变 */
  --success: #3ECF8E;
  --warning: #E0A355;   /* 成本、预算 */
  --danger:  #FF6B6B;
}
```

**关键规则：一屏最多 2 处渐变实心块。** 其余用渐变描边、渐变文字或 `--grad-subtle` 淡底。高饱和色铺开面积一大就刺眼，这是最容易翻车的地方。

### 11.3 组件升级清单

| 组件 | 现状 | 升级 |
| --- | --- | --- |
| **智能体输入条** | 无 | 新的视觉主角。渐变描边（1.5px），聚焦时 `--glow-primary`，内嵌快捷技能芯片 |
| 主按钮 | 渐变实心 | 保持，加 hover 辉光过渡 |
| 顶栏导航 | 胶囊 + 淡渐变底 | 提高饱和度，选中项加 1px 渐变描边 |
| 侧栏选中项 | 淡渐变底 | 改为左侧 2px 渐变竖条 + 极淡底，减少色块面积 |
| 卡片 / 节点 | 统一圆角 + 阴影 | 分层：普通节点仅描边；选中项才上辉光。避免"人人都是卡片" |
| **待确认节点** | 无 | 渐变虚线描边 + 2s 呼吸动画，和普通节点一眼可分 |
| **自主性档位** | 无 | 分段控件。`auto` 档用 `--warning` 而非渐变——它是警示不是强调 |
| **成本显示** | 无 | 等宽数字 `tabular-nums`，琥珀色，超限变红 |
| **进度阶段** | 转圈 | 渐变进度条 + 阶段文字 |
| 状态徽章 | 纯色底 | 语义色 12% 透明底 + 同色文字，更轻 |

### 11.4 动效

高饱和 + 深色容易显得廉价，动效要克制：

| 场景 | 动效 | 时长 |
| --- | --- | --- |
| 待确认节点出现 | 从 0.96 缩放淡入，逐个延迟 60ms | 240ms |
| 接受计划 | 虚线描边收敛为实线，辉光闪一次 | 320ms |
| 成本数字变化 | 数字滚动，不要直接跳 | 200ms |
| 输入条聚焦 | 辉光渐显 | 180ms |
| 生成中 | 渐变进度条流动 | 循环 1.8s |

全部包在 `@media (prefers-reduced-motion: reduce)` 里可关。

### 11.5 排版与留白

TapNow 观感的一半来自留白，不是颜色：

- 内容区左右内边距从 24px 提到 32px（≥1600px 时 44px）
- 节点卡片内边距 12px → 16px
- 分隔线用 `--border-soft`，几乎不可见
- 标题字重降一档（700 → 600），靠字号和留白拉层级，不靠加粗

### 11.6 落地顺序

1. **色板替换**——只改 `styles.css` 顶部变量和 `main.tsx` 的 ConfigProvider token，全局立刻生效，零组件改动
2. **减少渐变面积**——侧栏选中项、状态徽章改成低饱和承载
3. **新增智能体组件**——输入条、待确认节点、档位控件、成本条
4. **动效与留白**——最后做，属于打磨

前两步和智能体功能无关，**可以先做、独立见效**。

## 12. 分阶段

| 阶段 | 内容 | 交付标准 |
| --- | --- | --- |
| **A0** | LLM 客户端 + 配置 + 连通性自检 | 启动日志出现「智能体模型已连通：qwen-plus」 |
| **A0.5** | 前端色板升级（§11.6 前两步） | 与智能体解耦，可独立验收 |
| **A1** | 工作台「提示词参谋」+ 理由展示 + 成本估算 | 一句话 → 提示词 + 参数 + 预估金额，填进输入框 |
| **A2** | 技能库 + 画布编排 + 待确认预览层 + **计划状态机** | 一句话 → 待确认节点 → 接受后可运行；重复接受被拒 |
| **A3** | 自动档 + 三道成本闸门 + 计划回放 | 超限自动降级并说明原因 |
| **A4** | 自定义技能、模板库 | 用户能存自己的配方 |

**A2 必须同时交付状态机和成本估算**，不能推到 A3——那两样是防重复扣费和防超支的核心。

## 14. 风险

| 风险 | 应对 |
| --- | --- |
| **成本失控**（最大） | 三道闸门 + 状态机防重复 + 每日上限；A2 就位，不能拖 |
| 模型填错参数 | schema 校验 + 计划级重试预算 + 降级为人工选择 |
| 提示词注入 | 模型输出只能落进受约束 schema |
| 内容违规 | 系统提示词约束 + 审核错误码不重试 |
| 小模型 JSON 不稳 | 文档标明推荐模型；解析失败重试一次后明确报错 |
| 高饱和色刺眼 | 一屏最多 2 处渐变实心块；语义色不参与渐变 |
| 智能体挡了熟练用户的路 | 三个入口并存：手工搭、技能一键、智能体，随时可绕开 |
| token 成本不可见 | `agent_turns` 记录 tokens 与金额，管理页可查 |
